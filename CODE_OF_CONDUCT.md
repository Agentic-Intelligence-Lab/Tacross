# Code of conduct

## The short version

Be straight with people. Argue about the code, not the person writing it. Assume
the other person is competent and acting in good faith until they prove
otherwise.

## Expected behaviour

- Critique ideas with evidence: a failing test, a counterexample, a citation.
- Say when you are unsure. "I think this breaks on Windows but I have not tested
  it" is more useful than a confident guess.
- Respect that people work in different languages, time zones, and hardware
  situations. Not everyone has a GPU, a robot, or a fast connection.
- Keep review comments about the change, not the contributor.

## Unacceptable behaviour

- Harassment, insults, or sustained disruption in any project space.
- Sexualised language or attention, in any space.
- Publishing someone's private information without permission — including
  absolute paths, hostnames, and recordings of people who did not consent.
- Dismissing a report of a problem because you cannot reproduce it.

## Scope

Issues, pull requests, discussions, and any space where you are representing the
project.

## Enforcement

Report a problem to the maintainer through GitHub (open an issue asking for a
private channel, or use the security advisory form if the report is sensitive).
Reports are handled privately. Responses scale with the behaviour: a clarifying
comment, then a warning, then removal from the project space. The maintainer
recuses themselves from any report about their own conduct, and the reporter may
ask for a second opinion from any regular contributor.

## Attribution

This is a project-specific code of conduct rather than an adopted template, so
that the enforcement path is real rather than a placeholder address. It follows
the spirit of the [Contributor Covenant](https://www.contributor-covenant.org/),
version 2.1.
